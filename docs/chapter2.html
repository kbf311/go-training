Chapter 02

環境構築とGoの第一歩

Goのインストールからプロジェクト初期化、TypeScriptエンジニア向けの文法入門

2-1 Goのインストールと環境確認

Go言語の開発環境は非常にシンプルです。ランタイムやコンパイラが1つのインストーラにまとまっています。

インストール手順

  1. 公式サイト（go.dev/dl/）からお使いのOS（Windows / macOS / Linux）向けのインストーラをダウンロードします。
  2. Windowsの場合は .msi、Macの場合は .pkg を実行して画面の指示に従いインストールします。
  3. ターミナル（PowerShellやCommand Prompt）を開き、以下のコマンドでバージョンが表示されるか確認します。
# バージョンの確認
$ go version
go version go1.22.x windows/amd64
豆知識：GOPATHについて
昔のGoは $GOPATH という専用フォルダ以下にすべてのコードを置くルールがありましたが、現在のGo（Go Modules導入後）は 好きなフォルダ（任意の作業ディレクトリ）で自由に開発できます。 環境変数の複雑な設定は一切不要です。

2-2 Goプロジェクトの作成（初期化）

Node.jsでいう npm init -y（package.json 生成）に相当するのが、Goの go mod init です。

# プロジェクトフォルダを作成して移動
$ mkdir backend
$ cd backend

# Goモジュールの初期化 (モジュール名を指定)
$ go mod init backend

📄 go.mod（Node.js の package.json に相当）

モジュール名、Goの言語バージョン、依存している外部ライブラリの一覧が自動管理されます。

📄 go.sum（Node.js の package-lock.json に相当）

インストールしたライブラリのチェックサム（暗号ハッシュ）が記録され、改ざん防止と安全な再現ビルドを保証します。

2-3 TypeScriptエンジニアのためのGo文法のキモ

GoとTypeScriptはどちらも「静的型付け」ですが、思想にいくつか決定的な違いがあります。重要な3大ポイントを押さえましょう。

1 TypeScriptの interface ≒ Goの struct（構造体）

TypeScriptのオブジェクト型定義は、Goでは struct を使います。また、JSONキー名とのマッピングは「構造体タグ（`json:"id"`）」で指定します。

TypeScript (interface)
interface Monster {
  id: number;
  name: string;
  element: string;
}
Go (struct)
type Monster struct {
    ID      int64  `json:"id"`
    Name    string `json:"name"`
    Element string `json:"element"`
}

※Goでは先頭が大文字のフィールド（ID, Name）のみ、外部パッケージやJSON変換からアクセス可能（公開）になります。

2 try-catch は使わない！ 戻り値 if err != nil

Goには一般的な例外（Exception）スローがありません。失敗する可能性がある関数は、戻り値の最後に error を返します。

TypeScript (try-catch)
try {
  const data = await fetchData();
  console.log(data);
} catch (err) {
  console.error("失敗:", err);
}
Go (if err != nil)
data, err := fetchData()
if err != nil {
    log.Printf("失敗: %v", err)
    return
}
fmt.Println(data)

※一見冗長に見えますが、「どこでエラーが起き、どう対処しているか」がコードを読むだけで100%把握できる堅牢な設計思想です。

3 短縮変数宣言 := と 型推論

関数内では msg := "Hello" のように := を使うことで、型を明示せず自動推論で変数を宣言できます（TypeScriptの const / let と同じ手軽さ）。
