Chi (go-chi/chi/v5)

HTTP ルーター

標準の net/http に100%準拠した軽量高速なルーティングライブラリ。独自のcontextを持たず標準ハンドラーシグネチャをそのまま扱えるため、GoのWeb開発デファクトスタンダードの1つです。

go-chi/cors

CORS ミドルウェア

ブラウザからのクロスオリジン通信を制御します。Next.js（ポート3000）からGo（ポート8080）へのCookie（認証セッション）送信を AllowCredentials: true で安全に許可します。

sqlc

型安全コード生成

開発者が生SQL（queries/*.sql）を書くだけで、Goの型付き構造体と実行関数を自動生成するツール。ORMの「遅い」「ブラックボックス」問題を解決し、コンパイル時にSQLミスを検知できます。

modernc.org/sqlite

Pure Go SQLite

C言語コンパイラ（GCC等）が不要な純Go（Pure Go）実装のSQLiteドライバ。Windows環境でもCgoのインストールなしに go run や go build が一発で動作します。

3-2 ライブラリのインストール方法

Node.jsの npm install <package> に対応するのが go get <package> です。

# 外部ライブラリの追加 (go get)
$ go get github.com/go-chi/chi/v5
$ go get github.com/go-chi/cors
$ go get modernc.org/sqlite

# 不要な依存関係の整理・go.sumの同期
$ go mod tidy
💡 Tip：go mod tidy の習慣
Goでは、コード中で import しているのに go.mod にないものを自動追加し、逆に使わなくなったライブラリを削除してくれる go mod tidy コマンドが極めて優秀です。何かライブラリを追加・削除したら叩くのが定石です。

3-3 Go言語側でのAPI実装と処理フロー

リクエストを受信してからDBへアクセスし、JSONを返却するまでの全体の流れは以下のようになります。

sequenceDiagram autonumber actor User as 👤 Next.js (ブラウザ) participant Chi as Chi Router (main.go) participant Handler as Handler (monster_handler.go) participant Service as Service (monster_service.go) participant DB as SQLite DB User->>Chi: GET /api/monsters (Cookie付与) Chi->>Handler: ルーティング・HTTP受信 Handler->>Service: GetAllMonsters(ctx) Service->>DB: SELECT * FROM monsters ORDER BY id DB-->>Service: レコード配列 []Monster Service-->>Handler: []Monster, nil Handler-->>User: HTTP 200 OK (JSONレスポンス)

1. ルーティング定義（Chi）

URLパスとハンドラーを紐付けます。backend/cmd/api/main.go では以下のように定義しています。 

r := chi.NewRouter()

// ミドルウェア登録 (ログ出力やCORS)
r.Use(chimw.Logger)
r.Use(cors.Handler(corsOptions))

// API ルート定義
r.Route("/api", func(r chi.Router) {
    // モンスター一覧取得
    r.Get("/monsters", monsterHandler.ListMonsters)
    // ログイン処理
    r.Post("/login", authHandler.Login)
})

2. ハンドラーの実装例（JSONを返す）

w http.ResponseWriter にレスポンスを書き込み、r *http.Request からリクエスト情報を取り出します。 

// モンスター一覧を返すハンドラー
func (h *MonsterHandler) ListMonsters(w http.ResponseWriter, r *http.Request) {
    // 1. サービスのビジネスロジックを呼び出す
    monsters, err := h.service.GetAllMonsters(r.Context())
    if err != nil {
        http.Error(w, "データ取得に失敗しました", http.StatusInternalServerError)
        return
    }

    // 2. ヘッダーを application/json に設定
    w.Header().Set("Content-Type", "application/json")
    
    // 3. GoのstructをJSONにエンコードして出力
    json.NewEncoder(w).Encode(monsters)
}

3-4 Next.js 側からの呼び出し方法

Next.js（TypeScript）側からは、標準の fetch を使ってGoのAPIを呼び出します（frontend/lib/api.ts）。 

// frontend/lib/api.ts の呼び出し関数
const API_BASE = "http://localhost:8080/api";

export async function fetchMonsters(): Promise<Monster[]> {
  const res = await fetch(`${API_BASE}/monsters`, {
    method: "GET",
    credentials: "include", // ★重要: Cookie (認証セッション) を送信
    headers: {
      "Content-Type": "application/json",
    },
  });

  if (!res.ok) {
    throw new Error(`APIエラー: ステータスコード ${res.status}`);
  }

  return res.json();
}
Next.js 連携時の最重要ポイント：credentials: "include"
別オリジン（ポート3000から8080）にリクエストを送る際、デフォルトではブラウザはCookieを送信しません。credentials: "include" を指定し、Go側で AllowCredentials: true を設定することで、安全なセッションCookie認証が成立します。
